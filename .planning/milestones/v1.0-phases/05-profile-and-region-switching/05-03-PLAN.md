  <files>internal/ui/overlay/profile.go</files>
  <action>
In `NewProfileOverlay()`, immediately after the four existing list configuration calls
(`SetShowTitle`, `SetShowStatusBar`, `SetFilteringEnabled`, `DisableQuitKeybindings`),
add two more calls:

```go
l.SetShowPagination(false)
l.SetShowHelp(false)
```

These must appear BEFORE `l.Select(selectedIdx)` (order within the list setup block does
not technically matter, but keep them grouped with the other chrome-disable calls for
readability).

Why: bubbles/list.updatePagination() deducts chrome height from the available list height
before computing PerPage. With showHelp=true (2 rows: padding-top=1 + content=1) and
showPagination=true (1 row: empty pagination placeholder still counts), 3 of the 4
available rows are consumed by chrome, leaving PerPage=1 — forcing 2 pages for 2 items.
Disabling both eliminates all chrome rows; PerPage = 4 / 1 = 4, fitting all profiles on
one page.

Do NOT change the height calculation formula (`overlayH = len(profiles) + 6`). The formula
is not the issue; the issue is the chrome consuming the headroom.
