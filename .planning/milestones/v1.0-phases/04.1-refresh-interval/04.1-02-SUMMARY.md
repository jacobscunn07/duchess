# Phase 4.1 Plan 02: UI Observability — Refresh Interval and Last-Refreshed Timestamp Summary

**One-liner:** Status bar shows active interval as "Xs" and S3/ECS breadcrumbs show HH:MM:SS last-refreshed timestamp between refresh cycles, closing both UAT visibility gaps.

## What Was Built

Two UI additions that make the configurable refresh interval fully observable without changing any functional behavior:

1. **Status bar interval indicator** (`internal/ui/status.go`): The left group now reads "duchess | profile | region | Xs" where X is `cfg.RefreshInterval`. Added `fmt` import, new `intervalStyle` lipgloss var (color "33", inherits `statusBarStyle`), and extended `leftStr` with `fmt.Sprintf("%ds", m.cfg.RefreshInterval)`.

2. **Breadcrumb last-refreshed timestamp** (`internal/ui/s3/model.go`, `internal/ui/ecs/model.go`): Added `lastRefreshed time.Time` field to both Model structs. Set `m.lastRefreshed = time.Now()` in all data-loaded message handlers. Updated `renderBreadcrumb` in both models: spinner shows during active refresh/load; timestamp (HH:MM:SS) shows when idle and `lastRefreshed` is non-zero.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Also clear m.refreshing in bucketsLoadedMsg handler**
- **Found during:** Task 2
- **Issue:** The plan stated bucketsLoadedMsg "sets loading=false, refreshing=false" but the existing handler only cleared `m.loading`. The `s3RefreshTickMsg` sets `m.refreshing = true` before firing `FetchBucketsCmd`. Without clearing `m.refreshing` in `bucketsLoadedMsg`, the refreshing flag would stay true after a bucket-list refresh completed, leaving the spinner visible indefinitely.
- **Fix:** Added `m.refreshing = false` to `bucketsLoadedMsg` handler alongside the new `m.lastRefreshed = time.Now()` line.
- **Files modified:** internal/ui/s3/model.go
- **Commit:** 43747f4
